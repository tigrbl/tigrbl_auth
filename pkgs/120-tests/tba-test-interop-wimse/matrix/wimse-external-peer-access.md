## Run the external workload support slices

Run `tests/run_go_spiffe_batch.py` with a go-spiffe and Defakto qualification snapshot, their verifier bridges, and the frozen expanded `--manifest`. Choose one of the following runtime bindings.

- `--teleport-container` takes a container with tbot serving `/tmp/tba-workload.sock` and the SPIRE CLI at `/opt/spire/bin/spire-agent` as the Workload API client. The Teleport test workload uses `spiffe://example.org/workload-0` and permits Unix UID 0. UID 1001 exercises the refusal.
- `--mintid-container` takes a driver container on the MintID development stack's network. Use the pinned source and dependencies, add `test-harness/trace` and the source packages to `PYTHONPATH`, and mount `tests/mintid_bridge.py` at `/tbafixture/mintid_bridge.py`. Configure the issuer, verifier, chain RPC, relay URLs, and `ANCHOR_DIST` for that development stack. The runner checks the bridge digest before collecting cases.

The runner writes JUnit, an attempt journal, and the mapping from runtime pins to published IDs. The [per-ID report](wimse-external-support-per-id.csv) reconciles those IDs against the frozen inventory.
